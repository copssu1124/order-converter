# 쇼핑쇼츠 만들기

해외 상품 영상 여러 개에서 좋은 구간만 뽑아 한국어 쇼핑쇼츠를 만든다.
GPU도 유료 API도 쓰지 않는다.

## 준비 (한 번만)

```bash
pip install edge-tts imageio-ffmpeg opencv-python-headless numpy
```

맥(Apple Silicon 포함)·윈도우·리눅스 모두 같은 명령이다. ffmpeg는 `imageio-ffmpeg`가
플랫폼에 맞는 바이너리를 자동으로 가져오므로 따로 설치하지 않는다.

아래 명령의 `~/.claude/skills/shopping-shorts/scripts/` 는 맥·리눅스 기준이다.
윈도우(PowerShell)에서는 `$HOME\.claude\skills\shopping-shorts\scripts\` 로 바꾸고,
`python3` 대신 `python` 또는 `py` 를 쓴다.

## 전체 흐름

1. **원본 확인** — 어디에 자막·워터마크가 있는지 먼저 눈으로 본다
2. **대본 작성** — 후기나 상품 정보를 근거로 직접 쓴다 (아래 규칙)
3. **스펙 JSON 작성**
4. **렌더**
5. **검증** — 무음·정지 구간을 수치로 확인한다

---

## 1. 원본 확인

```bash
python3 ~/.claude/skills/shopping-shorts/scripts/detect_subtitle.py 원본.mp4 --preview 확인.png
```

`--preview`로 나온 png를 열어 빨간 상자(자막)와 노란 상자(워터마크)가 실제
글자를 덮고 있는지 본다. 엉뚱한 데를 잡았으면 스펙의 `mask.regions`에 좌표를
직접 넣는다.

## 2. 대본 쓰기

**사용자가 후기나 상품 정보를 주면 그것을 근거로 쓴다. 없으면 먼저 요청한다.**
지어내지 않는다 — 확인되지 않은 수치(용량, 시간, 인증)를 쓰면 과장광고가 된다.

규칙:

- 한 줄 **6~11자**. 길면 화면에서 잘린다
- 첫 줄은 **문제 제기나 결론**. 제품 이름으로 시작하지 않는다
- 중간은 **후기에서 자주 나온 순서대로**. 사람들이 실제로 신경 쓰는 순서다
- 마지막은 행동 요청 한 줄
- 8~12줄이면 15~25초가 나온다

좋은 예 / 나쁜 예:

| | |
|---|---|
| O | `물 뜨러 가는 거 귀찮으셨죠` |
| X | `혁신적인 대용량 보온병 출시!` |
| O | `6시간 뒤에 따라봤는데` |
| X | `놀라운 보온력을 자랑합니다` |

후기를 여러 편 분량으로 한 번에 받았다면 **대본을 15~20개 만들어 저장해두고**
영상마다 하나씩 쓴다. 매번 다시 쓰지 않아도 된다.

## 3. 스펙 JSON

```jsonc
{
  "output": "결과.mp4",
  "voice": "ko-KR-SunHiNeural",   // 여성. 남성은 ko-KR-InJoonNeural
  "rate": "+20%",
  "max_cut": 0.87,                 // 컷 하나의 최대 길이(초)
  "loudness": -12,                 // 최종 음량(LUFS)
  "mask": "auto",                  // 원본 자막·워터마크 자동 탐지 후 가림
  "style": {
    "font": "Pretendard JJ",
    "size": 107,
    "outline": 7,
    "shadow": 3,
    "margin_v": "auto"             // 원본 자막이 있던 자리에 한글 자막을 얹는다
  },
  "scenes": [
    { "src": "원본1.mp4", "text": "물 뜨러 가는 거 귀찮으셨죠" },
    { "src": "원본2.mp4", "text": "이거 하나면 하루가 끝나요" }
  ]
}
```

같은 원본을 여러 장면에 반복해서 넣어도 된다. 장면마다 **원본에서 서로 다른,
움직임이 많은 구간**을 자동으로 골라 쓴다.

BGM을 넣으려면 `"bgm": "음원.mp3"` 한 줄을 추가한다. 말할 때 자동으로 작아진다.
**유튜브 쇼츠 음악 라이브러리는 쓰지 않는다** — 수익이 절반으로 깎인다.
자세한 이유와 나머지 설정은 `reference.md`에 있다.

## 4. 렌더

```bash
python3 ~/.claude/skills/shopping-shorts/scripts/make_shorts.py 스펙.json
```

## 5. 검증 — 반드시 한다

```bash
# 말 사이가 비지 않는가 (0이어야 한다)
ffmpeg -i 결과.mp4 -af "silencedetect=noise=-45dB:d=0.12" -f null -

# 화면이 멈추지 않는가 (0이어야 한다)
ffmpeg -i 결과.mp4 -vf "freezedetect=n=0.003:d=0.4" -f null -

# 음량이 맞는가 (-12 LUFS 근처)
ffmpeg -i 결과.mp4 -af ebur128 -f null -
```

`ffmpeg`가 PATH에 없으면 `python3 -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"`
로 경로를 얻어 그것을 쓴다.

셋 중 하나라도 어긋나면 사용자에게 보내기 전에 고친다.

## 목표 수치

실제 인기 쇼츠 7편을 측정한 값이다. 결과물이 여기서 크게 벗어나면 손본다.

| 항목 | 목표 |
|---|---|
| 컷 길이 | 0.87초 |
| 첫 3초 컷 수 | 5~6개 |
| 자막 세로 위치 | 상단 19% 근처 |
| 글자 크기 | 107 (1080x1920 기준) |
| 음량 | -12 LUFS |
| 무음 구간 | 0개 |

## 소재가 얼마나 필요한가

소재 1초당 쓸만한 컷 0.5개가 나온다. **완성본 길이의 2.5배가 최소, 3~4배가 권장.**
30초 쇼츠면 원본 90~120초, 즉 15~20초짜리 영상 5~8개다.

길이보다 **장면 다양성**이 중요하다. 같은 영상에서 20컷을 뽑아도 같은 각도가
반복될 뿐이다. 스튜디오컷 1~2개 + 사용 장면 2~3개 + 클로즈업 1~2개 + 들고 다니는
컷 1개로 섞는다.

## 레퍼런스에서 규격 뽑기

닮고 싶은 쇼츠가 있으면 감으로 맞추지 말고 잰다.

```bash
python3 ~/.claude/skills/shopping-shorts/scripts/analyze_reference.py 레퍼런스1.mp4 레퍼런스2.mp4 ...
```

컷 길이·자막 위치·글자 크기·움직임량을 재서 스펙에 넣을 `style` 블록을 내준다.
3~5편이면 충분하다.

## 반드시 지킬 것

- **원본이 남의 영상이면 저작권과 유튜브 재사용 콘텐츠 정책이 걸린다.** 자막을
  지워도 원본 저작권은 남는다. 나레이션을 새로 얹고 컷을 새로 짜는 재편집이
  들어가야 한다. 사용자가 이미 알고 있더라도 처음 한 번은 짚어준다.
- **확인되지 않은 제품 정보를 대본에 쓰지 않는다.** 용량·보온 시간·재질·인증은
  사용자가 준 자료에 있는 것만 쓴다.
- **검증 3종을 돌리기 전에 결과물을 전달하지 않는다.**

자세한 설정과 각 기능의 근거는 `reference.md`를 읽는다.
