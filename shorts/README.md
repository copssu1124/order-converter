# 쇼핑쇼츠 생성기

상품 소재(이미지 또는 영상 클립)와 나레이션 문구만 주면 **1080x1920 세로 쇼츠**를
자동으로 뽑아준다. 유료 프로그램 없이 전부 무료 도구로 돌아간다.

## 무엇이 자동인가

| 단계 | 처리 |
|---|---|
| 나레이션 음성 | edge-tts (한국어 3종, 무료·API 키 불필요) |
| 무음 제거 | TTS 음성 앞뒤에 붙는 빈 소리를 잘라내 대사가 끊기지 않게 한다 |
| 장면 길이 | 나레이션 길이에 맞춰 자동 계산, 프레임 단위로 정렬 |
| 화면 | 9:16으로 꽉 채우고, 이미지는 켄 번스 줌 / 영상은 구간 컷 |
| 자막 | 흰 굵은 글씨 + 검은 외곽선, 장면 전체를 덮어 빈 화면이 없다 (libass로 영상에 구움) |
| 최종 | H.264 + AAC, 유튜브·인스타 바로 업로드 가능 |

## 설치

```bash
pip install edge-tts imageio-ffmpeg
```

시스템에 ffmpeg가 있으면 그걸 쓰고, 없으면 imageio-ffmpeg 내장본을 자동으로 쓴다.
ffmpeg는 `libass`가 포함된 빌드여야 자막이 구워진다.

## 실행

```bash
python3 make_shorts.py sample_thermos.json
```

## 스펙 파일

```jsonc
{
  "output": "결과.mp4",
  "voice": "ko-KR-SunHiNeural",   // 여성. 남성은 ko-KR-InJoonNeural
  "rate": "+18%",                  // 말 속도
  "gap": 0.05,                     // 컷 끝나고 다음 컷까지 여백(초)
  "lead": 0.0,                     // 컷 바뀌고 말이 시작될 때까지 여백(초)
  "style": {
    "font": "Pretendard JJ",
    "size": 92,                    // 자막 크기
    "outline": 7,                  // 검은 외곽선 두께
    "shadow": 3,
    "margin_v": 500                // 화면 아래에서 자막까지 거리(px)
  },
  "scenes": [
    { "src": "assets/00.jpg", "text": "화면에 보일 자막", "say": "읽을 문장(생략 시 text와 동일)", "zoom": 0.12 }
  ]
}
```

- `src`는 이미지(jpg/png)와 영상(mp4/mov/mkv/webm) 둘 다 된다.
- **영상 소재는 장면마다 원본의 다음 구간을 이어서 쓴다.** 모든 장면이 0초부터
  재생되면 같은 그림이 반복돼 정지 화면처럼 보이기 때문이다. 특정 구간을
  지정하려면 장면에 `"in": 12.5` (초)를 넣는다. 원본이 모자라면 되감아 잇는다.
- 결과가 정지 화면처럼 보이면 원본 자체에 움직임이 있는지 먼저 확인한다.
  `ffmpeg -i 결과.mp4 -vf "freezedetect=n=0.003:d=0.5" -f null -`
- `text`는 6~10자로 짧게 끊는 것이 쇼츠 자막의 기본이다.
- `say`를 따로 두면 자막과 읽는 문장을 다르게 할 수 있다(숫자·단위 읽기 교정용).

## 대사 사이가 비면 안 된다

쇼츠는 말이 끊기는 순간 시청자가 넘긴다. 이 도구는 두 가지를 자동으로 처리한다.

1. **TTS 음성의 앞뒤 무음 제거.** edge-tts가 내주는 mp3에는 앞뒤로 0.5초 안팎의
   빈 소리가 붙어 있다. 그대로 이어붙이면 컷마다 1.3초씩 말이 끊긴다.
   `silenceremove`로 양쪽을 잘라낸 뒤 이어붙인다.
2. **자막이 장면 전체를 덮는다.** 말이 끝났다고 자막까지 지우면 화면이 빈다.

`gap`은 기본 0.05초다. 이 값을 0.2초 이상으로 올리면 컷마다 정적이 생기므로
특별한 이유가 없으면 건드리지 않는 편이 좋다. 결과물의 무음 구간은 아래로 확인한다.

```bash
ffmpeg -i 결과.mp4 -af "silencedetect=noise=-45dB:d=0.12" -f null -
```

## 원본에 박힌 자막·워터마크 자동 제거

중국·해외 쇼츠를 소재로 쓸 때, 원본에 박혀 있는 자막과 워터마크를
**위치를 손으로 지정하지 않고** 찾아서 가린다. GPU도 OCR도 필요 없다.

```bash
python3 detect_subtitle.py 원본.mp4 --preview 확인.png   # 어디를 찾았는지 눈으로 확인
```

스펙에 한 줄만 넣으면 제작 과정에 자동으로 들어간다.

```jsonc
{
  "mask": "auto",                       // 자막·워터마크 자동 탐지 후 가림
  "style": { "margin_v": "auto" }       // 원본 자막이 있던 자리에 한글 자막을 얹음
}
```

### 어떻게 찾는가

| 대상 | 신호 | 처리 |
|---|---|---|
| **박힌 자막** | 밝은 글씨 + 바로 옆 어두운 외곽선. 사진에는 거의 없는 조합 | 블러로 뭉갬 |
| **워터마크** | 반투명이라 색은 변하지만, **모든 프레임의 같은 자리에 윤곽선**이 남음 | `delogo`로 주변을 끌어와 메움 |

`margin_v: "auto"`가 핵심이다. 가린 자국 **위에** 한글 자막을 얹으므로
블러 자국이 글자에 덮여 티가 나지 않는다.

세부 조정은 `mask`를 객체로 준다.

```jsonc
"mask": { "mode": "blur", "strength": 28, "regions": "auto" }
// mode: blur(뭉갬) | box(검은 상자로 확실히 덮음)
// regions: "auto" 또는 [{"x":0,"y":1500,"w":1080,"h":140}, ...] 직접 지정
```

### 한계

탐지는 **글씨가 밝고 외곽선이 있는** 일반적인 쇼츠 자막을 기준으로 한다.
배경이 아주 복잡하거나, 자막이 화면 안에서 움직이거나, 색이 배경과 비슷하면
놓칠 수 있다. `--preview`로 먼저 확인하고, 필요하면 `regions`에 직접 넣는다.

## 움직임이 많은 구간만 골라 쓴다

쇼츠는 화면이 멈추는 순간 넘어간다. 앞에서부터 순서대로 잘라 쓰면 원본의
정적인 구간까지 그대로 들어가 결과가 밋밋해진다.

그래서 원본의 **초 단위 움직임량 곡선**을 만들고, 장면마다 아직 안 쓴 구간 중
가장 활발한 곳을 골라 쓴다. 기본으로 켜져 있고, 끄려면 `"lively": false`.

실측(스튜디오 제품 촬영 원본 2개 기준):

| | 평균 움직임 | 거의 정지한 프레임 |
|---|---|---|
| 원본 그대로 | 5.7 ~ 6.6 | — |
| 순서대로 자름 | 7.1 | 3.1% |
| **활발한 구간 우선** | **10.4** | 5.0% |
| (참고한 실제 인기 쇼츠) | 11.9 | 7.0% |

확인 명령:

```bash
ffmpeg -i 결과.mp4 -vf "freezedetect=n=0.003:d=0.4" -f null -
```

## 자막을 박스형으로

배경이 복잡한 영상 위에서는 외곽선보다 **검은 반투명 판**이 훨씬 잘 읽힌다.
실제 인기 쇼츠들이 쓰는 방식이다.

```jsonc
"style": {
  "box": true,                 // 글자 뒤에 판을 깐다
  "pad": 18,                   // 판 여백
  "box_color": "&H73000000",   // ASS 색 표기(앞 두 자리가 투명도, 클수록 투명)
  "size": 92,
  "margin_v": "auto"           // 원본 자막이 위에 있으면 위, 아래면 아래에 배치
}
```

`margin_v: "auto"`는 컷마다 따로 계산한다. 원본 자막이 위에 있는 영상과 아래에
있는 영상을 한 편에 섞어 써도 각각 알맞은 자리에 얹힌다.

## 레퍼런스에서 규격을 뽑아낸다

"이런 느낌으로" 대신, 잘 나가는 쇼츠를 넣고 **수치를 재서** 설정값을 정한다.

```bash
python3 analyze_reference.py 레퍼런스1.mp4 레퍼런스2.mp4 ...
```

컷 길이·첫 3초 컷 수·자막 위치·글자 크기·움직임량·무음 총합을 재고, 마지막에
`style` 블록과 목표치를 바로 쓸 수 있는 형태로 출력한다.

실제 인기 쇼츠 7편을 재본 결과:

| 항목 | 중앙값 | 범위 |
|---|---|---|
| 컷 길이 | **0.87초** | 0.60 ~ 1.80 |
| 첫 3초 컷 수 | **5.5개** | 2 ~ 6 |
| 자막 세로 위치 | **19.3%** (상단) | 12 ~ 31% |
| 글자 크기(1080x1920 기준) | **107** | 83 ~ 179 |
| 박스 배경 | 6편 중 1편만 | 대부분 외곽선 |
| 무음 총합 | **0초** | 전편 BGM |

## 컷을 빠르게 넘긴다

대사 한 줄이 컷 하나가 되면 컷이 1.5초씩 늘어져 밋밋해진다. 그래서 대사가
`max_cut`보다 길면 **그 안에서 화면만 여러 번 갈아 끼운다.** 자막과 나레이션은
끊기지 않고 그대로 이어진다.

```jsonc
"max_cut": 0.87        // 컷 하나의 최대 길이(초). 기본 0.9
```

적용 전후(같은 소재·같은 대사):

| | 컷 길이 | 첫 3초 컷 수 | 평균 움직임 |
|---|---|---|---|
| 대사당 컷 1개 | 1.10초 | 4개 | 16.4 |
| **max_cut 0.87** | **0.74초** | **6개** | **18.5** |
| (레퍼런스 7편 중앙값) | 0.87초 | 5.5개 | 12.0 |

## 음량 맞추기

그냥 뽑으면 -17 LUFS 안팎으로 나온다. 실제 인기 쇼츠를 재보면 -6 ~ -14 LUFS라
나란히 놓고 들으면 우리 것만 작게 들린다. `loudnorm`으로 목표 음량까지 올린다.

```jsonc
"loudness": -12        // 기본값. 레퍼런스 중앙값과 같은 수준
```

| | 음량 |
|---|---|
| 보정 전 | -17.0 LUFS |
| **보정 후** | **-11.9 LUFS** |
| 레퍼런스 7편 | -6.1 ~ -14.1 (중앙값 -11.5) |

확인:

```bash
ffmpeg -i 결과.mp4 -af ebur128 -f null -
```

## 소재는 얼마나 필요한가

실측으로 계산한다. 컷 하나가 0.87초, 겹치지 않게 0.35초를 띄우면 소재 1초당
**쓸만한 컷 0.5개**가 나온다(움직임이 그 영상 중앙값 이상인 구간 기준).

실제 소재 3편을 재본 값:

| 원본 | 길이 | 뽑을 수 있는 컷 | 그중 쓸만한 컷 |
|---|---|---|---|
| v1 (스튜디오) | 35.6초 | 29 | 20 |
| v2 (생활컷) | 19.0초 | 15 | 13 |
| v3 (리뷰) | 96.8초 | 79 | 44 |

따라서:

| 완성본 | 필요한 컷 | 최소 소재 | 권장 소재 |
|---|---|---|---|
| 15초 | 17개 | 35초 | 60초 |
| 20초 | 23개 | 45초 | 80초 |
| **30초** | **34개** | **70초** | **90 ~ 120초** |
| 45초 | 52개 | 105초 | 150초 |

**완성본 길이의 2.5배가 최소, 3~4배가 권장이다.**

다만 컷 수만 채우는 것과 잘 나오는 것은 다르다. 같은 영상에서 뽑은 컷은 결국
같은 각도가 반복되므로, **길이보다 영상 개수와 장면 다양성**이 중요하다.
한 제품당 15~20초 영상 5~8개, 구성은 이렇게 섞는 것이 좋다.

- 제품 단독 스튜디오컷 1~2개
- 실제 사용 장면 2~3개
- 디테일 클로즈업 1~2개
- 사람이 들고 다니는 컷 1개

## BGM — 유튜브 쇼츠 음악은 쓰지 않는다

유튜브 쇼츠에서 **음악 라이브러리 곡을 쓰면 내 수익이 깎인다.** 음원 수익을 받는
쪽은 음원 권리자지 영상 올린 사람이 아니다.

| 쇼츠에 쓴 음악 | Creator Pool로 가는 비율 |
|---|---|
| 음악 없음 | **100%** |
| 유튜브 음악 1곡 | **50%** |
| 2곡 | **33%** |

나머지는 음원 라이선스 비용으로 빠지고, 크리에이터는 Pool에서 다시 45%를 받는다.
반면 **로열티프리 음원은 배분이 없다.** 그래서 유튜브 픽커를 쓰지 말고 로열티프리
음원을 여기서 직접 깐다. 나레이션과의 균형도 이쪽이 제어된다.

```jsonc
{
  "bgm": "음원.mp3",
  "bgm_volume": 0.22,    // 나레이션 대비 BGM 크기
  "bgm_duck": true,      // 말할 때 BGM을 자동으로 줄인다 (기본 켜짐)
  "bgm_fade": 0.6        // 시작·끝 페이드(초)
}
```

`bgm_duck`은 사이드체인 압축이다. 나레이션이 나오는 순간 BGM이 눌리고 말이
끝나면 다시 올라온다. 깔아만 두면 말소리를 잡아먹고, 안 깔면 말 사이가 빈다.

검증값(같은 영상, BGM 유무만 다름):

| | 평균 음량 | 최대 |
|---|---|---|
| 나레이션만 | -14.3 dB | -1.5 dB |
| **BGM + 더킹** | **-14.3 dB** | **-1.5 dB** |

BGM을 넣어도 나레이션 음량이 그대로다 = 말소리를 밀어내지 않는다는 뜻이다.
전체 음량은 -11.9 LUFS로 유지되고 무음 구간은 0개다.
